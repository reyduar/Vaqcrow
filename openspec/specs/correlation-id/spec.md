# Correlation ID Specification

## Purpose

Define a portable, opaque UUID v4 contract and server-controlled HTTP propagation without expanding into domain schema or observability concerns.

## Requirements

### Requirement: Public Correlation ID Contract

`packages/contracts` MUST expose a branded UUID v4 schema, its opaque `CorrelationId` type, a parser that accepts unknown input, and a generator through its public barrel. Zod 4 MUST be a direct runtime dependency of the package.

#### Scenario: Public contract is available

- GIVEN a consumer of the contracts package
- WHEN it imports the correlation ID schema, type, parser, and generator from the public barrel
- THEN every named contract is available
- AND values validated by the schema are compatible with the branded type

#### Scenario: Raw strings remain unbranded

- GIVEN an arbitrary string that has not passed the correlation ID contract
- WHEN it is used where a `CorrelationId` is required
- THEN static type checking rejects the assignment

### Requirement: Runtime Validation

The schema and parser MUST accept valid UUID v4 values from unknown input and MUST reject malformed values, non-string values, and UUIDs of other versions. Rejection MUST NOT make Zod error messages, paths, codes, or structure a stable project contract.

#### Scenario: Valid UUID v4 is accepted

- GIVEN unknown input containing a valid UUID v4 string
- WHEN the input is parsed
- THEN parsing succeeds with a branded `CorrelationId`

#### Scenario: Invalid input is rejected

- GIVEN unknown input that is malformed, non-string, or a valid UUID of a non-v4 version
- WHEN the input is parsed
- THEN parsing fails
- AND no particular internal error representation is guaranteed

### Requirement: Correlation ID Generation

The generator MUST return a valid branded UUID v4. A conformance sample of 1,000 generated values MUST contain no duplicates; this bounded check MUST NOT be interpreted as a mathematical uniqueness guarantee.

#### Scenario: Generated sample is valid and distinct

- GIVEN an empty collection
- WHEN 1,000 correlation IDs are generated
- THEN every value passes the correlation ID schema
- AND the collection contains 1,000 distinct values

### Requirement: Server-Controlled HTTP Propagation

Fastify MUST assign each request a server-generated `CorrelationId` as `request.id` and MUST return the exact same value in the `x-correlation-id` response header. Caller-supplied correlation IDs MUST NOT be accepted or reused in this scope.

#### Scenario: Server-generated request ID is propagated

- GIVEN a request without a correlation ID header
- WHEN Fastify handles the request
- THEN `request.id` is a valid UUID v4 generated by the server
- AND `x-correlation-id` equals that exact `request.id`

#### Scenario: Caller-supplied ID is not reused

- GIVEN a request with a valid `x-correlation-id` header
- WHEN Fastify handles the request
- THEN the supplied value is not selected as `request.id`
- AND the response header equals the server-generated `request.id`

### Requirement: Architectural Portability

Contracts, application, and domain code MUST NOT import web frameworks or infrastructure-provider APIs. The contracts public barrel MUST remain consumable by web-targeted builds without requiring a Node-only module.

#### Scenario: Dependency boundaries remain clean

- GIVEN the contracts, application, and domain source graphs
- WHEN dependency boundaries are evaluated
- THEN no framework or infrastructure-provider import crosses into those areas

#### Scenario: Web consumer resolves the barrel

- GIVEN a web-targeted consumer of `packages/contracts`
- WHEN its build resolves the public barrel
- THEN resolution succeeds without a Node-only module requirement

### Requirement: Bounded Capability Scope

This capability MUST NOT define domain states, event/API/adapter schemas owned by issue #38, or tracing, telemetry, resilience, and observability behavior owned by issue #98.

#### Scenario: Unrelated contracts remain absent

- GIVEN the completed correlation ID capability
- WHEN its public contracts and runtime behavior are inspected
- THEN no issue #38 domain or transport schema has been added
- AND no issue #98 observability or resilience behavior has been added
